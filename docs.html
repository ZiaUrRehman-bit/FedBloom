What is Federated Learning?

Federated Learning (FL) is a technique that trains a shared AI model across multiple devices or organisations without ever moving the raw data. Each participant trains locally on their own data; only model updates (not data) travel over the network. The server aggregates these updates into a single improved global model.

💡
Example: Five hospitals each train on their own patient records. No patient data leaves any hospital. The resulting global model is better than any single hospital could have trained alone.

What makes FedBloom different?

Traditional federated learning requires Python expertise, knowledge of frameworks like Flower or TensorFlow Federated, and hours of configuration. FedBloom replaces all of that with a desktop GUI — pick your model, upload your data, click Run.

Installation

Windows Installer (recommended)

1

Download FedBloom-Setup.exe from the website.

2

Run the installer and follow the prompts. No admin rights required for a per-user install.

3

Launch FedBloom from the Start Menu or Desktop shortcut.

Run from Source (developers)

# Clone the repository
git clone https://github.com/ziaurrehman-bit/FedBloom
cd FedBloom/files/fedbloom-stage-D/fedkit

# Install in editable mode
pip install -e .

# Launch
fedkit
ℹ️
Python 3.10+ is required when running from source. The Windows installer bundles its own Python runtime.

First Launch

When FedBloom opens you will see the Welcome Screen. This is the starting point for every session.

1

A splash screen appears while services initialise (usually 2–5 seconds).

2

The Welcome Screen shows two cards: Enter as Server and Enter as Client. Choose your role for this session.

3

You can switch roles at any time using the arrow icon at the bottom of the sidebar.

Server vs Client

Every federated learning session has two types of participants:

🖥
Server
Orchestrates the FL plan. Creates experiments, sets configuration, starts training rounds, and aggregates model updates from clients.
📡
Client
Brings local data. Connects to the server, receives the global model, trains locally on private data, and returns updates.
💡
For a simulation (all on one machine), you only need the Server role — FedBloom spawns virtual clients internally. Real network deployment requires separate machines running the Client role.

Creating Experiments

Experiments are the core unit of work in FedBloom. Each experiment defines a complete FL training job.

Create a new experiment

1

Navigate to Experiments in the sidebar. Click + New Experiment.

2

Enter an experiment name and optional description.

3

Select your Dataset, Model, Aggregation strategy, and Partitioner from the dropdowns.

4

Set Number of clients, Rounds, Local epochs, Batch size, and Learning rate.

5

Choose Simulation (single machine) or Real Network deployment mode.

6

Click Save. The experiment appears in the list, ready to run.

Custom CSV datasets

You can upload any CSV file as a dataset. FedBloom handles all preprocessing automatically:

  • Last column is treated as the label / target
  • Numeric columns are z-score normalised
  • String/categorical columns are one-hot encoded
  • Data is split 80/20 into train and test sets
  • Rows are distributed across clients using the selected Partitioner
ℹ️
CSV format: First row must be a header. Missing values should be removed before upload. Minimum 50 rows recommended for meaningful training.

Aggregation Strategies

The aggregation strategy controls how client model updates are combined into the global model.

StrategyBest forPlan
FedAvgGeneral use. Averages client weights proportional to dataset size.Free
FedProxNon-IID data. Adds a proximal term to handle heterogeneous clients.Pro
KrumByzantine robustness. Detects and ignores potentially malicious clients.Advanced

Partitioners

Partitioners control how data is distributed across clients — crucial for realistic experiments.

PartitionerDescription
IIDIndependent & Identically Distributed. Each client gets a random uniform sample. Ideal baseline.
DirichletNon-IID distribution using a Dirichlet concentration parameter. Models real-world heterogeneity.
Label ShardEach client receives data from only a subset of classes. Extreme non-IID scenario.
CustomSpecify exact sample counts per client. FedBloom auto-scales if totals exceed dataset size.

Running & Monitoring

Starting a run

Select an experiment from the list and click ▶ Start. FedBloom will:

  1. Initialise the FL server and virtual clients (simulation) or wait for real clients (deployment)
  2. Begin round 1 — each client trains locally and sends updates
  3. Aggregate updates and broadcast the new global model
  4. Repeat for all configured rounds

Live metrics dashboard

While training runs, the Charts tab shows live plots:

  • Global accuracy — model accuracy on the global test set per round
  • Global loss — training loss curve
  • Precision / Recall / F1 — per-class metrics bar chart
  • ROC curve — with AUC score
  • Computation cost — seconds per round
  • Communication cost — MB exchanged per round
  • CPU / GPU utilisation — live resource usage
  • Memory utilisation — RAM and GPU memory

Topology view

The Topology tab shows a visual graph of connected clients with their training status:

  • Blue — idle / waiting
  • Orange — training locally
  • Green — completed, update sent
  • Red — error

Results & Artefacts

Results tab

After training, the Results tab shows a table with per-client and global metrics for every round. You can export this as a CSV file.

Artefacts tab

The Artefacts tab lists all saved model files and metadata:

  • training_metadata.json — full experiment configuration
  • metrics_all_rounds.csv — all metrics for all rounds
  • round_XXX_global_model.pkl — saved global model per round

Click Download Bundle to export all artefacts as a ZIP.

💡
Saved .pkl model files can be loaded directly in Python using pickle.load() for inference or further fine-tuning.

Local Network Deployment

When all participants are on the same WiFi or LAN:

1

Server: create an experiment, select Real Network mode, note the displayed IP address and port.

2

Clients: open FedBloom, choose Enter as Client, enter the server IP and port, click Connect.

3

Server: once enough clients appear in the Topology view, click ▶ Start.

Tailscale VPN (cross-network)

For participants on different networks (e.g., different hospitals, home offices):

  1. Install Tailscale on every machine.
  2. All machines join the same Tailscale network (or a shared Tailnet).
  3. Use the machine's Tailscale IP (e.g., 100.x.x.x) as the server address.
  4. No port forwarding or firewall rules needed — Tailscale handles NAT traversal.

Public IP + Port Forwarding

If Tailscale is not an option:

  1. Find your server's public IP (search "what is my IP" in a browser).
  2. In your router, create a port forward rule: external port → server machine's local IP, port 8080.
  3. Ensure your OS firewall allows inbound connections on port 8080.
  4. Clients connect using your public IP and the forwarded port.
⚠️
Security note: Port forwarding exposes your machine to the internet. Use a firewall allowlist by IP where possible, or prefer Tailscale for production deployments.

Hyperparameter Optimisation (HPO) Pro

HPO automatically searches for the best training configuration. Navigate to HPO in the sidebar:

  1. Select the experiment to optimise.
  2. Choose the metric to maximise (accuracy, F1) or minimise (loss).
  3. Define search ranges for learning rate, batch size, local epochs.
  4. Set the number of trials and click Run HPO.
  5. Results show the best configuration — apply it to your experiment with one click.

Privacy & Security Pro

Differential Privacy (DP-SGD)

Enable DP in the experiment configuration to add mathematically guaranteed privacy noise to client updates. This prevents the server from reconstructing raw training data from model weights.

  • Noise multiplier — higher = more privacy, lower accuracy
  • Max grad norm — clips gradients before adding noise

Krum Aggregation

Krum filters out model updates that deviate significantly from the majority — protecting against poisoning attacks from compromised clients. Available on the Advanced plan.

AI Assistant Advanced

The AI Assistant (powered by a local Ollama LLM) helps you interpret experiment results, suggest configurations, and explain model behaviour.

Setup

  1. Install Ollama from ollama.com.
  2. Pull a model: ollama pull llama3
  3. In FedBloom Settings, set the Ollama base URL (default: http://localhost:11434) and model name.

Open the Assistant section in the sidebar to start a conversation about your experiments.

Use Case: Healthcare

🏥
Multi-Hospital Diagnostic Model
Healthcare · Patient Privacy

Problem: Five hospitals want to train a chest X-ray classification model. Patient data cannot leave each hospital due to HIPAA / GDPR regulations.

FedBloom solution:

  1. Each hospital installs FedBloom on a local workstation.
  2. One hospital acts as Server; the rest are Clients.
  3. Server creates experiment: Model = CNN, Dataset = custom X-ray CSV, Aggregation = FedAvg.
  4. Clients connect via Tailscale. Each trains on their local patient records.
  5. After 20 rounds, the global model outperforms any individual hospital's model.
✅
Enable Differential Privacy to add a provable privacy guarantee — no patient record can be reconstructed from shared model updates.

Use Case: Finance & Banking

🏦
Cross-Bank Fraud Detection
Finance · Regulatory Compliance

Problem: Six banks want to improve fraud detection. Transaction data is commercially sensitive and regulated — sharing is not permitted.

FedBloom solution:

  1. Each bank exports a transaction CSV with features (amount, time, merchant category) and a fraud label.
  2. Upload CSVs locally to each bank's FedBloom instance (data never leaves the bank).
  3. Server creates experiment: Model = XGBoost, Partitioner = Dirichlet (realistic non-IID).
  4. Aggregate with Krum to guard against a potentially compromised participant.
  5. Global model catches fraud patterns that no single bank's local model could detect.

Use Case: Genomics

🧬
Disease Gene Prediction Across Research Labs
Genomics · Research

Problem: Research institutions each have genomic datasets but cannot share raw sequences due to participant consent agreements.

FedBloom solution:

  1. Each lab uploads their genomic feature CSV. FedBloom auto-encodes categorical allele data.
  2. Model = MLP or DNN, Rounds = 30, Local epochs = 5.
  3. Use the AI Assistant to interpret SHAP feature importances — which genes matter most?
  4. Export the trained global model for deployment in clinical decision-support systems.

Use Case: Insurance

🛡
Federated Risk Scoring
Insurance · Actuarial

Problem: Multiple insurance companies want a better risk model but can't pool policyholder data.

FedBloom solution:

  1. Each insurer prepares a CSV of policy features and claim outcomes.
  2. Model = Random Forest, Aggregation = FedAvg, Clients = number of insurers.
  3. Run HPO to find the optimal number of trees and max depth.
  4. The resulting global risk model is more accurate and less biased than any single company's model.

Use Case: Academic Research

🎓
Reproducible FL Benchmarking
Academia · Research

Problem: A researcher wants to benchmark FedAvg vs FedProx on non-IID data without writing framework code.

FedBloom solution:

  1. Create two experiments with identical settings, changing only the aggregation strategy.
  2. Use Dirichlet partitioner (α = 0.1) for strong non-IID simulation.
  3. Run both, export metrics CSVs, compare accuracy and convergence speed.
  4. Save plots directly from the Charts tab for publication figures.
ℹ️
All experiments are stored in a local SQLite database at ~/.fedbloom/fedbloom.db. You can query it directly for custom analysis.
